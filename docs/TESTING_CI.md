# Testing strategy и CI

**CI-only.** Этот документ определяет текущие обязательные проверки, а не хронологию PR. Фактическая готовность: [STATUS](STATUS.md); исторические решения и свидетельства отдельных этапов: [IMPLEMENTATION_PLAN](IMPLEMENTATION_PLAN.md) и [ADR](adr/). Метрики и история оптимизаций CI: [CI_PERFORMANCE](CI_PERFORMANCE.md). Не считать исследовательский тест готовой функцией.

## 1. Порядок GitHub Actions

Источник исполнения: [workflow](../.github/workflows/ci.yml). На PR и push в main запускаются specification и ci-gate. Для обычного изменения кода обязательны 13 jobs с учётом OS matrix, плюс условный `format-repair` (skipped на чистом SHA):

| Job | Обязательные проверки |
| --- | --- |
| specification | Markdown links, TOML/schema и контракты, syntax/F-14 guest network, CI DAG, docs-only classifier, independent TLS probe, timing validation; fail-fast Rustfmt preflight всех трёх workspaces. |
| rust-tests (Linux) | Locked all-target tests, Clippy с `-D warnings`, реальный Linux binary для cross-host acceptance. |
| windows-smoke | Native all-target tests, PTY/ConPTY, отдельный opt-in disposable WinINet CAS/recovery, cross-logon Named Pipe kernel denial, staging Windows artifacts. |
| m0-1-api-spike / m0-1-windows-spike | Изолированный Rust crate: strict TLS/H2 и QUIC/H3, full-duplex, flow credit, cancellation, BBR/CUBIC с детерминированной потерей/задержкой; Python/OpenSSL independent H2 interoperability и negative CA/hostname. |
| m3-4-btls-spike (Linux/Windows) | Изолированный BoringSSL TLS/H2, first-flight, PKI, duplex, Clippy. |
| m3-4e-btls-production-feature (Linux/Windows) | Реальный production H2 backend, строгая TLS/PKI и SmartTheia, Clippy. |
| browser-e2e (Linux/Windows) | Pinned Chromium: независимая H2 reference и функциональная навигация через оба транспорта Theia, H2 и H3, с guarded origin/DOM assertion. |
| f14-cross-host | После native Linux/Windows jobs: настоящий Linux WSL2 kernel/server и native Windows client; protected import, H2/H3 HTTP CONNECT/SOCKS5, wrong CA/token и замена credential. |
| ci-gate | Fail-closed aggregation по exact head; обязательный failed/skipped/cancelled job запрещает merge. |

- После specification независимые native jobs выполняются параллельно. `f14-cross-host` ждёт Linux/Windows artifacts. Используются pinned dependencies, committed lockfiles и `Swatinem/rust-cache`; устаревшие runs одной ветки отменяются.
- Полные release builds по явному `workflow_dispatch`; обычные PR не дублируют их. Без root Cargo.toml/Cargo.lock production validation не считается выполненной.
- Docs-only fast path допускается только при доказанном Git diff из обычных non-executable Markdown add/modify/delete в allowlist. Неизвестный diff, rename/type/mode changes и non-Markdown запускают full native. Specification и ci-gate остаются обязательными.
- Rustfmt drift: `specification` форматирует локально и доказывает, что diff содержит только изменения tracked regular `.rs`; грязный SHA падает до native fan-out. `format-repair` только для собственной PR-ветки, не main/base/fork, создаёт один проверенный дочерний commit с lease на точный head и явно запускает `workflow_dispatch` на новом SHA. Перед push проверяется ancestry текущего PR base; отставшую ветку нужно синхронизировать. Новый CI проверяет SHA и base ancestry, запускает всю матрицу без release-сборки и без повторного auto-repair. `ci-gate` требует skipped repair на зелёном прогоне. Синтаксическая ошибка, не-Rust diff, конфликт ветки, отсутствие прав или ошибка dispatch блокируют merge. Никаких formatter overlays или post-green commits.
- Никаких обязательных локальных ручных smoke-тестов. Для автоматизированной приёмки использовать loopback/изолированные VM, ephemeral PKI/credentials, machine-checkable assertions и cleanup. Не обращаться к внешним production endpoints.

## 2. Контракт автоматизированных проверок

### Unit, протокол и конфигурация

- Golden bytes, arbitrary splitting/aggregation, payload 0/65536/65537, unknown types/version/flags, bounded decoder, per-stream FSM, terminal states, OPEN_OK gate, FIN/ABORT. Deterministic malformed bytes; coverage-guided fuzz и property gates должны автоматизироваться перед релизом.
- Strict TOML v1: unknown/missing fields, duplicate IDs/hashes, explicit inbound grants, invalid DNS/IPv6/port, wildcard/dual-stack bind conflicts, timeouts, UTF-8, unknown TLS profile, secret refs, запрет `system_proxy=on`. Markdown TOML examples обязаны синтаксически разбираться.
- Bounded input и guarded atomic writes: size, native path/reference rules, final symlink/reparse, Unix private modes/Windows protected credential ACL, stale editor, busy lock, concurrency winner, pre/post-replacement uncertainty, crash recovery. Не заявлять доказательство power-loss или защиты произвольных untrusted parent paths.
- TUI keyboard/focus, masking, clean/dirty state, compact terminal, save ≠ Apply, cancel and separate confirmation. Invalid args и unsupported OS fail closed до runtime/OS side effects.

### Реальные сетевые и системные проверки

- H2/TLS1.3 и H3/QUIC/TLS1.3 real loopback: strict CA/hostname/SAN/ALPN (включая incompatible/absent QUIC ALPN), no 0-RTT, actual BBR at both QUIC endpoints, byte-exact relay, full-duplex before request EOF, slow readers/backpressure, half-close, abrupt EOF, bounded timeouts, concurrent streams и cancellation с живыми siblings.
- Production relay liveness (ADR-0081): parallel native H2/H3 matrix, each with upload-only and download-only traffic across the real 30s deadline, both half-close orderings and fully idle termination. Paused-clock tests prove empty DATA cannot extend the shared idle budget, tail deadline starts only after opposite FIN and stalled-direction progress does not mask errors. H2 trailers after FIN must reset, matching H3 trailer refusal. No extra CI job; new cases unverified until exact-head CI.
- Auth/inbound ACL: missing/wrong/disabled/ungranted bearer, constant-time digest, HTTP refusal, limits/quotas/rate budgets, server-side DNS with post-resolution IP ACL and pinned dial, denied private/reserved destinations, no dial on denial. Loopback test destinations require explicit test-only `allow_private_ips=true`.
- Auto fallback: только pre-auth observed UDP silence после фактической отправки; wrong CA/SNI/ALPN/bearer/protocol/OPEN и post-handshake errors не дают downgrade. Test negative TTL, local source change и stale generation.
- Compiled CLI through real HTTP CONNECT/SOCKS5/curl/Chromium, success strictly after OPEN_OK, no local DNS for target. Независимые H2 и H3 tests; browser navigation не доказывает wire parity.
- IPC (ADR-0038–0052): private Linux Unix socket и Windows SID-DACL Named Pipe; real cross-logon denial; read-only status/restart readiness; revision/content-bound auth CAS; actual PTY/ConPTY confirmation, stale/dirty/cancel/client refusal; supervised fresh-port cutover, same-port TLS rotation, exact PEM pin, quota resize, bounded one-shot TLS rollback. Reject busy binds, wrong SAN/PEM, mixed edits, stale revision and lost ACK ambiguity; existing runtime/tunnels follow documented drain/authorization semantics.
- Windows F-07 (ADR-0056, 0077, 0079): disposable native user only, explicit consent, manual mode, local binds before apply, durable journal and exact snapshot/restore, foreign override, live owner busy, hard-exit recovery without Drop. PR #112 passed compiled ConPTY H2 CONNECT/SOCKS5, consent/cancel, stale TOML/snapshot, missing/replaced journal, off-mode, restore/stop/drop and hard-kill/recovery; v1 PAC/proxy/autodetect and IPv6 fixtures. ADR-0079 extends the same mandatory native tests with per-user policy registry fixtures, global/legacy mutex contention, already-restored and replaced recovery record. PR #114 accepted with native CI. No extra job or mock substitution; named VPN, actual domain GPO, multi-session upgrade remain open.
- F-14 (ADR-0053–0055, 0064, 0066–0073): issuance/disable/rotation/recovery, tokenless public link, masked local import and independent CA, protected file export and credential-only replacement, exact saved bytes and conflict rollback, no implicit activation or live Apply. [F14_ACCEPTANCE](F14_ACCEPTANCE.md) maps positive and negative native and real VM cross-host evidence; physical host transfer and power-loss remain open.
- F-18 research (ADR-0021–0037, 0059–0066): real verified TLS exporter and H2/H3 DATA identity experiments, actual QUIC Initial observation, reconnect/channel binding, negative replay/key and local key/checkpoint lifecycle, passive discovery, consented exact-target/dual probe, DNS pin/freshness, bounded batches, no fabricated evidence or unapproved network traffic. Research-only trust model, not a production security mode.

## 3. Performance, fingerprint и diagnostics

- Сравнивать одинаковые workload/host и H2/H3 отдельно: throughput, RTT/jitter p50/p95/p99, CPU, peak RSS, allocation, 1%/5% loss, pacing/fairness и H3→H2 fallback. Тяжёлые полные benchmarks запускать автоматически на стабильных isolated release runners, не на каждом PR; заранее зафиксировать release thresholds. Synthetic CI comparison подтверждает исполнение эксперимента, не превосходство BBR.
- F-13: default rustls baseline, named BoringSSL H2 profile, реальные pinned Chromium H2 SETTINGS/HPACK/pseudo order и отдельно QUIC/H3 first-flight/transport-parameter reference. Go/uTLS снят с требований (ADR-0074); Python/OpenSSL independent strict H2 preserved. ADR-0076 подтверждает функциональную H3 navigation (PR #111), но native browser QUIC wire reference и full packet parity не доказаны. Публиковать измеренные различия, не обещать DPI invisibility.
- Safe trace (ADR-0058, 0075, 0078): default `info`, только типизированные статические/numeric/boolean fields; `THEIA_TRACE_LEVEL=debug` для промежуточных stages, `trace` для отдельных кадров; `THEIA_TRACE_OFF=1` имеет приоритет. CI сохраняет журналы при failure в изолированном каталоге. Native tests требуют отсутствие secret/argument leakage, default-on, filter/off, bounded rotation и concurrent private directory startup. Ни при каком уровне не писать raw payload, headers, credentials, endpoints, paths/config или private keys.
- CI timing сравнивать только complete successful first-attempt runs одинакового event/matrix через `scripts/ci-timing.py` и validated exported API metadata. Не путать sum job durations с billed runner minutes; без сопоставимых замеров не заявлять ускорение.

## 4. F-18/F-19: обязательная релизная security/benchmark матрица (ещё не завершена)

- **F-18 identity и fingerprint:** independent crypto/security review и native Linux/Windows H2/TCP + H3/QUIC real handshake tests для ключа сервера, invalid key/replay, active probes, strict TLS and bearer/inbound grants; никакой фиктивной VLESS/XTLS REALITY-совместимости. Recorded actual TLS/HTTP/QUIC fingerprints vs reproducible browser and authorized target references, без fake User-Agent.
- **M3.5b1 actual Rust engine:** `crates/theia/tests/camouflage_discovery.rs` запускается в обязательных Linux и Windows `cargo test --workspace --all-targets --locked`. Проверяет без каких-либо сетевых запросов: автоматический seed популярных HTTPS-доменов, IP interfaces vs NAT/egress uncertainty, отделение inferred BGP/RDAP от approved CIDR, сужение /24+, отказ /16 и чужого CIDR, IPv6 без sweep /64, reserved/private/CGNAT/documentation exclusion, dedup, 256 upper bound, нет fabricated TLS evidence. Рейтинг H2 и H3 раздельный, unknown score/confidence=0 и не eligible, untrusted TLS/rejected ALPN/fingerprint блокирует eligible. Успешные unit tests **НЕ** означают работающий scanner, certificate verification, active probe, REALITY, ECH или TLS-in-TLS protection.
- **M3.5b2a native TLS/H2 probe:** `crates/theia/tests/camouflage_probe.rs` выполняет только loopback TLS1.3/h2 с одноразовыми CA, проверяет реальный успешный handshake, пустой trust store, неверный CA/SNI/ALPN, неправильное/отсутствующее разрешение на точный сокет, handshake timeout и отсутствие заявлений о H3/fingerprint. Маршрутный UDP socket connect только читает локальный выбор source IP, не отправляет датаграмм. Модуль не делает внешние DNS, публичное сканирование или HTTP GET. Ограничения: 4 одновременных probes, общий deadline ≤5s, no retry/downgrade. `TlsEvidence` только при успешном verified TLS; F-13/F-18/F-19 остаются открытыми.
- **F-18 picker future M3.5b2b+:** deterministic offline tests автоматического поиска: собственный public IPv4/IPv6 и assigned CIDR, NAT/egress uncertainty, inferred RDAP/BGP ≠ ownership, CIDR bounds и отсутствие sweep без разрешения; встроенный seed-каталог google.com/samsung.com/amd.com и другие HTTPS-домены без обязательного ручного ввода, dedup и scope grouping; IP без SNI vs DNS with SNI, SAN/chain/expiry/TLS1.3/ALPN h2/h3 и unsupported/unknown. Score 0–100 **не** вероятность DPI-обхода, confidence, freshness; активные сети только в loopback/изолированном CI и только permissioned targets, bounds на concurrency/rate/bytes/deadline, invalid DNS/SSRF/private ranges/rebind/redirect/cancellation. No mass scans of external unrelated addresses. Серверный двухшаговый TUI тест с preview, IPC rollback, no auto Windows proxy и 60x18/80x24/120x40 view.
- **F-19 TLS-in-TLS:** настоящие byte-exact HTTPS-in-proxy H2/H3 потоки и потоковые тесты OPEN_OK/FIN/backpressure/лимитов, independent classifier nested TLS trained/tested on held-out browser/SmartTheia traces; сравнить traffic-shaping off/on по TPR при FPR≤1%, confidence, per transport, p95/p99 latency, throughput, CPU/peak RSS и bandwidth overhead. Числовые release thresholds принять до измерений; один padded-traffic pass без доказанного improvement не засчитывать. Не читать контент пользователей или private keys.
- **Текущий статус:** отдельные M3.5/M4.5 loopback/TUI/consent проверки уже реализованы и входят в обязательный CI, но релизные F-13/F-18/F-19 остаются P0 открытыми до полной криптографической, измерительной и cross-host E2E-приёмки. См. [STATUS.md](STATUS.md) и [STEALTH_REALITY.md](STEALTH_REALITY.md).

## 5. Release gates и merge

Required check: `ci-gate` на актуальном SHA; настройка branch protection отдельна. Все обязательные positive/negative native, security, browser и cross-host тесты сохраняются. Не заменять реальный E2E моками, не расширять skip rules и не удалять evidence ради экономии CI. До автоматизации и успешного выполнения всех независимых P0 gates, including F-07, F-11, F-13, F-14, F-18, F-19 и M5, релиз не допускается. Не считать test-only TLS primitives, partial fingerprint, синтетический benchmark или зелёный unit test полной приёмкой.

- ADR-0082/0083 (proposed): exact/fresh wizard review and own-cert guarded TOML save, explicit pinned TLS profile over H2/H3, wrong trusted pin/hostname/bearer/mode mismatch before target dial, correct byte-exact relays, real binary auto fallback only on observed UDP silence and terminal H3 pin mismatch, restart-only/mode and invite v1 refusal. Existing native matrix, no extra job; unverified until exact-head CI.

### Целевая приёмка ADR-0085 (ещё не выполнена)

Обязательны нативные E2E XHTTP × два security modes × H2/H3, для каждого QUIC-first и network-only fallback с неизменными identity/security/XHTTP/auth, отказ при TLS/key/ALPN/auth/protocol ошибках. REALITY wizard/manual формируют один тип и используют один валидатор. TLS только ручные cert/key paths, отказ при неверной паре, без wizard. Guarded Apply/rollback, byte-exact DATA, OPEN_OK, FIN, cancellation и backpressure. Матрица — нормативное требование, не результат тестирования.

**ADR-0086:** acceptance измеряет собственный SmartTheia contract, не Xray interoperability или побайтовое воспроизведение его handshake. Никакого требования копировать Xray XHTTP modes, REALITY key format или config. Нативные H2/H3 E2E каждого security mode, fallback, crypto/security review, F-13/F-19 независимые измерения, Apply/rollback и все existing mandatory checks остаются обязательными. Spec assertions защищают формулировки, но не заменяют behavioral tests.

### ADR-0087 replacement invitation and cross-host gate

ADR-0087: the sole replacement theia://v1/ invitation explicitly represents SmartTheia XHTTP, own TLS stream-one or intermediate pinned TLS stream-one/stream-up, and H2/H3/auto. The old default-only envelope is rejected; no v2, no compatibility adapter. CA remains independent; no runtime downgrade or activation. Full SmartTheia REALITY is not yet implemented. Existing mandatory F-14 cross-host job retains all prior scenarios and adds two Linux inbounds and native Windows CONNECT/SOCKS5 over H2/H3/auto with round-tripped pinned public invite, separate CA/credential, wrong pin and wrong carrier-mode refusal. Linux private key stays in Linux. No extra workflow or weakened gate.

### ADR-0088 channel binding acceptance

Mandatory existing workspace tests cover pure proof mutation/race and independent raw real TLS/H2 and QUIC/H3 same/fresh connection replay refusal. Existing full relay and cross-host pinned tests exercise the new adapter. No job or dependency version changes; exact-head CI required.
