# TUI / UX specification (ratatui)

**Задача:** понятная локальная консоль управления без веб-панели. И сервер, и клиент доступны из одного `theia tui`. Полноценный keyboard-first workflow, минимальное число модалок, ошибки по делу. Тексты основного интерфейса — русский, с перспективой en.

## 1. Информационная архитектура

```text
┌─────────────────────────────────────────────────────────────────────┐
│ THEIA  v0.x    Состояние: сервис не запущен          [?] Справка   │
├─────────────────────────────────────────────────────────────────────┤
│ [1] Для сервера                 [2] Для клиента                    │
├─────────────────────────────────────────────────────────────────────┤
│ Сервер: inbound(0)              Клиент: профиль не выбран         │
│ • Inbound и порты               • Профили и подключения           │
│ • Пользователи и права          • Локальный HTTP/SOCKS5           │
│ • TLS и политика                • Системный прокси Windows        │
│ • Состояние / диагностика       • Состояние / диагностика         │
├─────────────────────────────────────────────────────────────────────┤
│ Tab: переключить  Enter: открыть  ?: помощь  q: выход              │
└─────────────────────────────────────────────────────────────────────┘
```

Главное меню из двух явно подписанных карточек/колонок; на терминале шириной менее 80 колонок — вертикальная навигация. «Панель» означает локальный TUI-раздел, не браузерную admin panel.

### Серверный раздел

**Overview:** статус runtime, транспортные listeners (UDP H3, TCP H2), inbound count, connections, errors, последние reload outcomes. Если service не запущен, показывать **«Не запущен»**, не нулевые фиктивные метрики.

**Inbounds:** список ID / адреса / TLS domain / статус / users; клавиши создать, изменить, отключить, удалить. В форме группировать адреса/порты, TLS, политику. Валидация **на поле** и сводная перед сохранением. Удаление требует подтверждения и предупреждения об активных сессиях.

**Users:** список user ID и enabled state; создать CSPRNG-токен, показывать **только один раз**, копировать/экспортировать конфиденциальную ссылку или файл по явному подтверждению, revoke/rotate с предупреждением об отключении клиента. Обычный экспорт inbound без токена; старый токен из digest восстановить нельзя. Серверный TOML хранит только hash. Назначение ID пользователей **на inbound обязательно**: TUI показывает `allowed_user_ids`, отсутствие назначения считается ошибкой, а не разрешением всех пользователей.

**Settings & Diagnostics:** политика private destinations, caps/timeouts, config path, последняя ошибка. Токены, ключи, headers и payload не отображать.

### Клиентский раздел

**Profiles:** список импортированных/созданных подключений, название, endpoint, транспорт auto/h3/h2, auth token reference (по умолчанию скрыт), активный/неактивный статус; добавление по ссылке theia://v1/... или защищённому файлу с предпросмотром и проверкой. Активный профиль выделен и обозначен текстом; не обозначать только цветом.

**Connect:** поднять/остановить локальные listeners, выбранный транспорт «QUIC / HTTP/3» либо «TLS / HTTP/2» только после реального handshake, время последней проверки, причина fallback, число активных потоков. **Разделять** статусы «Локальный прокси слушает», «Транспорт авторизован», «TCP-туннель открыт (OPEN_OK)». Не показывать «Соединено» при одном лишь локальном bind или HTTP 200 на upstream.

**System proxy (Windows):** [Выключен/Управляется Theia/Настроен другим приложением/Требует восстановления]. Включение доступно только при `system_proxy="manual"` и отдельном подтверждении, **никогда автоматически при старте TUI/сервиса**. Отключение восстанавливает только принадлежащие Theia значения; ошибка ACL, PAC или конфликт не скрываются.

**Diagnostics:** проверка доступности профиля, TLS hostname, auth rejection, UDP unavailable, H2 success/fail — без раскрытия ключа.

### M4.5h: DNS домена из каталога и H2+H3 по закреплённым адресам

В серверной TUI `p→r→d` выбирается **один** из 14 встроенных доменов (j/k, без DNS). Enter показывает **согласие на DNS A/AAAA** с раскрытием запроса резолверу/третьим сторонам; только **y** отправляет один DNS-запрос с лимитом 5с. n/Esc ничего не отправляют. Ответы строго проверяются целиком: не более 64, любой private/loopback/link-local/непубличный IP или не-443 делает весь DNS-result недопустимым; не более 8 безопасных уникальных IP закрепляются на 60с **с момента завершения DNS lookup в worker, а не с момента обработки ответа TUI**. Задержанный ответ старше 60с и некорректный будущий timestamp целиком отбрасываются; после истечения срока без нового DNS подтверждение блокируется. Перед началом активной сети worker повторно проверяет оригинальный срок действия пинов ([ADR-0037](adr/0037-m4-5i-dns-pin-observation-freshness.md)). Нет автоматической TLS-проверки, даже если DNS успешно получен.

j/k выбирает pinned IP, Space отмечает конкретный адрес; Enter показывает **второе отдельное СОГЛАСИЕ** с точными `IP:443`, доменным SNI/SAN, двумя независимыми транспортами TCP/TLS1.3 ALPN=h2 и UDP/QUIC/TLS1.3 ALPN=h3, требованием независимого права тестирования **каждого** IP и жёсткими лимитами (2 одновременно, 5с/цель, 20с/набор). Только **второе y** запускает сеть. При actual probe нет DNS re-resolution или fallback на другой порт/IP. Esc отменяет запрос, удаляет пины при возвращении к каталогу; n отказывается. Отчёт по каждому IP хранит отдельные score/confidence H2/H3 или Unknown, суммарный dual count, **REALITY: НЕ готов**, никаких Apply и обещаний обхода DPI. [ADR-0036](adr/0036-m4-5h-consented-domain-dns-pinned-dual-tui.md).

### M4.5g: серверный TUI ручной пакет IP из offline-плана

После `p→r` оператор видит источники IP, каталог доменов (без DNS) и необязательный отдельно заявленный `a→CIDR→Enter→y` **только** для offline-плана. Нажать **b**, чтобы открыть список публичных IP из текущего плана: own assigned и дополнительные `Подсеть: заявлен оператором` подписаны по-разному. Ни один не отмечен автоматически. **j/k** выбирает строку, **Space** отдельно отмечает/снимает конкретный IP; максимум **8**. **Enter** открывает проверку с полным списком `IP:443` и одним выбранным TOML `server_name` как SNI для всех, двумя сетевыми транспортами на каждый IP, доверенными CA, пределом 2 in-flight, 5с/цель и 20с/набор. До Enter+y нет ни TCP, ни UDP. **y** после полного раскрытия разрешает *ровно перечисленные* адреса; **n** отказывается, **Esc** снимает подтверждение либо отменяет worker и закрывает. На старте только offline own IP. Без server config/SNI, назначения IP, выбранных Space галочек, native roots или валидного `ProbeApproval` сеть не запускается.

Каждый `IP` в ответе получает реальные раздельные H2 и H3 score/confidence либо отказ/Unknown. Отдельно показывается `Совместимы по H2+H3: N/M`; даже N=M не делает REALITY криптографически готовым. Баллы не вероятность обхода DPI. Нет автоматического сканирования CIDR/домена, нельзя считать маску интерфейса доказательством владения, нет Apply, runtime reload или системного прокси. Для активной проверки любого конкретного IP нужны самостоятельные права и явное повторное согласие. [ADR-0035](adr/0035-m4-5g-consented-cidr-dual-batch-tui.md).

### M4.5f: предохранители будущего пакетного подбора IP и доменов

API `probe_dual_batch` обрабатывает максимум 8 вручную разрешённых пар (IP:443, DNS SNI) в исходном порядке, не более 2 пар одновременно, максимум 20 секунд на весь пакет и 5 секунд на TCP/H2 и UDP/H3 handshake. **До первого пакета** проверяются права на каждый IP, точное совпадение SNI, наличие домена в каталоге и закреплённая `PinnedDomain {domain,pinned_ip}` пара, доверенные CA и offline-plan. При ошибке хотя бы одной цели весь пакет отказывается запускаться. Успех только H2 или только H3 оставляет кандидата неподходящим для обоих. **Это пока исключительно библиотечный механизм, новой автоматической кнопки сканирования или доменного TUI selector нет**: активные запросы к сторонним доменам без отдельного разрешения недопустимы. REALITY ready не заявлен. [ADR-0034](adr/0034-m4-5f-source-aware-dual-batch.md).

### M4.5e: подтверждение обоих транспортов, H2 + H3, для одного кандидата

Из серверного `p→t` выбирается один **назначенный** публичный IP и известный SNI выбранного inbound (не seed-домен, не адрес соседней CIDR). `Enter/t` показывает отдельное согласие на **два запроса** к **одному IP:443**: TCP/TLS1.3/CA/SNI/SAN/ALPN=h2 и UDP/QUIC/TLS1.3/CA/SNI/SAN/ALPN=h3. Только `y` запускает оба без HTTP и без DNS, Esc отменяет, `n` отказывает. Оба результата выводятся независимо: для настоящего H3 QUIC ALPN success H3 score **80/100** и confidence **85%** (fingerprint остаётся Unknown), для H2 success аналогичный H2 score. При неуспехе одного его score **Unknown**, и кандидат **не** помечается как совместимый с обоими; таймаут UDP не превращается в fallback. Даже при обоих успешных handshake **REALITY готов: НЕТ** до реализации полноценной криптографической аутентификации, HTTP/3 semantics, отпечатка Theia и F-19. Нет скрытых диапазонных/доменных сканов, автоматического применения или сохранения согласия. [ADR-0033](adr/0033-m4-5e-dual-h2-h3-candidate-gate.md).

### M4.5d: результаты и доказательства после ручного TLS/H2 probe

После `p→t→Enter→y` успешное TLS1.3/PKI/SNI/SAN/ALPN=h2 наблюдение выбранного IP:443 показывает объяснимые баллы из существующего `TlsEvidence::suitability`: H2 **80/100**, confidence **85%**, eligible **НЕТ** (не измерен Theia fingerprint). H3 **score Unknown**, confidence **0%**, eligible **НЕТ** (QUIC/H3 и его ALPN вообще не измерялись; H2 TLS не является H3 evidence). Показываются причины отсутствующих полей, реальная задержка handshake и сколько секунд прошло с получения результата. Score **не является вероятностью обхода DPI** и не утверждает readiness REALITY/TLS-in-TLS. Если адрес в отчёте не совпадает с выбранным, сертификат отклонён, ALPN не h2, произошёл timeout или иной сбой, **score Unknown**, без положительных утверждений. Эти результаты не открывают кнопку Apply, не создают CIDR approval и не записывают данные на диск. [ADR-0032](adr/0032-m4-5d-evidence-score-tui.md).

### M4.5c: группировка F-18 кандидатов и заявленный CIDR (только offline)

Из пассивного серверного экрана `p` нажать **r**: видно три группы «Подсеть сервера», «Популярные домены», «Добавленные вручную» с реальными числами, IP образцами и 14 не проверенными по сети HTTPS seeds. Все TLS/H2 данные по умолчанию Unknown: score 0/100, confidence 0%, **не** вероятность обхода DPI. `a` вводит свой IPv4 CIDR размером не шире /24 (до 64 ASCII bytes), Enter запускает **только offline** проверку существующим bounded planner: диапазон содержит фактический публичный UP IP локального интерфейса, не выходит за назначенную маску и не превышает предел списка. Появляется **канонический** CIDR (например, `93.184.216.10/29 → 93.184.216.8/29`), точное число дополнительных IP-кандидатов и предупреждение об отсутствии доказательств собственности. Только отдельное **y** показывает новых кандидатов в ephemeral offline-плане; **n/Esc** отвергают. Подтверждение на этом шаге **НЕ** является `ProbeApproval` и не может запустить `p→t` автоматически. На client/Home/Help и в ходе согласия ipify кнопка r недоступна. Сохранение TOML/системный прокси/IPC runtime не затрагиваются, результаты не сохраняются. [ADR-0031](adr/0031-m4-5c-candidate-groups-offline-cidr.md).

### M4.5b: ручная TLS/H2 проверка одного собственного IP (ограниченный срез)

В серверной TUI из пассивной панели `p` клавиша `t` открывает отдельный review TLS/H2 без сети. Выбор `j/k` допускает максимум 8 **действительно назначенных локальных публичных IP** с валидной маской; соседние адреса CIDR, приватные интерфейсы, чужие домены и даже публичный egress, сообщённый ipify (не назначенный локально), не становятся целями. Без загруженного `server.toml` и выбранного inbound с проверенным `server_name` запуск блокируется. Порт закреплён 443, нет DNS перебора или fallback на другой порт. `Enter/t` показывает подтверждение с выбранным IP:443/SNI и признанием оператором права проверки, только `y` запускает один TLS1.3/CA/SAN/ALPN=h2 handshake в рабочем потоке с native OS доверенными CA, 5s deadline и отменой по Esc. `n` не отправляет ничего. Результат не является score, REALITY или гарантией обхода DPI. Возврат к пассивной панели не меняет TOML/runtime/Windows proxy. [ADR-0030](adr/0030-m4-5b-explicit-single-ip-h2-tui.md).

### M4.5a: промежуточная панель «Сеть / публичный IP» (реализуемый ограниченный срез)

Клавиша **p** из серверной TUI (и без TOML config) открывает пассивную панель: действительные локальные Linux UP интерфейсы и маски, число возможных публичных IP и offline seed-кандидатов; на Windows локальный native collector честно показывает Unsupported. Никаких DNS, сканирования или сетевых probe при открытии. В панели **i** показывает отдельный экран явного **СОГЛАСИЯ НА ВНЕШНИЙ ЗАПРОС** к `https://api64.ipify.org/`: выбранный сервис узнает видимый публичный IP и DNS-запрос, результат не доказывает NAT/ownership; **y** инициирует один запрос TLS1.3 в отдельном потоке с системными CA и проверкой SNI/SAN, дедлайном ≤5s, **n** отменяет согласие, **Esc** закрывает панель и отменяет running worker. Отображаемый адрес является наблюдением внешнего сервиса, не основанием для active CIDR sweep или apply. Несохранённый черновик блокирует открытие панели; секреты никогда не выводятся. Runtime/system proxy/TOML не меняются. Этот этап **не** закрывает двухшаговый мастер F-18 или анти-DPI меры: результаты подбора/score/Apply не реализованы. [ADR-0029](adr/0029-m4-5a-consented-ip-discovery-panel.md).

### Целевая серверная панель F-18/F-19: мастер «Защита от DPI» (не реализовано)

В server TUI: Inbound → Защита от DPI → «Проверить и подобрать» → результаты → «Применить». **Две основные операции**, но подтверждения активного сетевого probing, работы с ключами и потенциально опасного применения остаются отдельными. При запуске **автоматически** определяется возможная публичная IP-подсеть сервера (с явной пометкой, кому она принадлежит) и формируется отдельный список популярных HTTPS-доменов: google.com, samsung.com, amd.com, microsoft.com, apple.com, github.com, cloudflare.com и другие. Ручной список необязателен. Видны три группы источников: «Подсеть сервера», «Популярные домены», «Добавленные вручную». Пассивный поиск по DNS/CT доступен без сетевого TLS-пробинга; активные TLS/443 проверки собственных/разрешённых IP и доменов требуют явного согласия и показывают CIDR, количество адресов и лимиты. Чужая/неподтверждённая подсеть не сканируется автоматически. Подробности docs/STEALTH_REALITY.md.

Результаты: кандидат IP/domain, TLS1.3/ALPN/SNI/cert наблюдения и фактическая поддержка fingerprint Theia для H2/H3, score 0–100 с причинами, confidence/freshness и явным «балл ≠ вероятность обхода DPI», unknown/unsupported/rejected. «Применить» делает предпросмотр validated typed TOML, транзакционный IPC/rollback, не меняет Windows system proxy и не объявляет runtime активным раньше подтверждения. Режим REALITY-подобный, не VLESS/REALITY совместимый. Отсутствие пригодных целей показывает честный отказ.

TLS-in-TLS в расширенных настройках: будущий переключатель off/optional/required, измеренный эффект на статистику внешних потоков, p95/CPU/RSS/overhead и показ рисков. Unsupported required запрещает соединение, не выключается скрыто. Не отображать содержание TLS приложений, bearer/private keys или пользовательские URL.

## 2. Навигация и клавиатура

| Клавиши | Действие |
| --- | --- |
| `1` / `2` | серверная / клиентская панель с главного экрана |
| `Tab` / `Shift+Tab` | следующий / предыдущий фокус в формах |
| `↑/↓` или `j/k` | перейти по списку |
| `Enter` | открыть/выбрать/подтвердить |
| `Esc` | назад или отменить диалог (без потери изменений) |
| `Ctrl+S` | проверить и сохранить |
| `Ctrl+R` | запросить reload (когда доступен, с подтверждением) |
| `?` / `F1` | контекстная помощь |
| `q` | выход (не срабатывать при вводе текста) |

Все действия должны иметь видимую подсказку в нижней строке; горячие клавиши не должны срабатывать во время ввода секретов или текста.

## 3. Формы, состояния, обратная связь

- В каждой форме есть `*`/«Не сохранено»; при Esc/q диалог «Сохранить / Отменить изменения / Остаться».
- Save != Apply: после сохранения показывать «Сохранено в TOML; runtime ещё не обновлён», если reload не сделан. M4.2a предоставляет лишь **Linux CLI read-only** `theia server status` при явном приватном `THEIA_CONTROL_DIR`, без интеграции TUI, ревизии или разрешения Apply; в TUI runtime остаётся «состояние неизвестно» ([ADR-0038](adr/0038-m4-2a-linux-readonly-management-ipc.md)). M4.2b0 добавляет отдельный CLI `theia server reload --check` **без применения и без статуса Applied**: strict candidate TOML / loaded TLS PEM fingerprint comparison, live H2/H3 listeners остаются неизменными, TUI Apply по-прежнему запрещён ([ADR-0039](adr/0039-m4-2b0-readonly-reload-preflight.md)). При успешном reload показывать время и snapshot revision.
- Валидация с именем поля и способом исправления: «server.inbounds[0].h2_listen: порт 443 занят», а не «ошибка 0x3».
- Долгая операция — индикатор прогресса, возможность отмены; UI event loop никогда не блокируется на DNS, TLS или file IO.
- Важные статусы показывать и **цветом, и текстом**. High-contrast варианты, не полагаться на Unicode-иконки, совместимость 16-color терминалов.
- Минимальный экран 80x24; адаптивный layout ниже этой ширины, а при экстремально малом терминале понятное уведомление о недостатке места без panic.
- Скрывать token references на screen sharing при включённом privacy mode; секрет показывать только после отдельного действия и не оставлять на экране после смены панели.
- Учитывать терминал без мыши; mouse support optional. TUI корректно восстанавливает terminal raw mode/alternate screen при panic/error/kill, где это технически возможно.

## 4. Потоки взаимодействия (UX acceptance)

**Сервер: создать inbound:** server → Inbounds → New → id/binds → TLS → users → review → Ctrl+S → apply/reload → status. Невалидный путь cert блокирует apply, но пользователь может сохранить черновик отдельно только при явной маркировке.

**Клиент: подключиться:** client → Profiles → Import link/file либо Add manually → preview endpoint/TLS/transport и предупреждение о секретном приглашении → отдельная проверка CA/credential storage → Validate → Save → выбрать активный профиль → Start local proxy («Слушает»). При первом реальном HTTP CONNECT или SOCKS5 запросе дожидаться OPEN_OK и только затем показывать «Туннель открыт». Диагностика произвольного внешнего адреса требует выбранной пользователем цели; не посылать неожиданный probe в сторонний сервис.

**Windows proxy:** client → System proxy → Activate → просмотр предыдущих настроек → confirm → snapshot → apply → уведомление. Disconnect/crash recovery по контракту конфигурации.

## 5. Архитектура TUI и тесты

Unidirectional pattern `Model + Event → Update(Model, Command[]) → View`. UI state отделён от эффекта (запись TOML, RPC, proxy OS). В тестах fake effects/events: клавиатура, отображение ошибочных полей, сохранение/отмена, обнаружение dirty, безопасный выход, смена роли, нулевой список inbound, терминал 60x18/80x24/120x40, screen snapshot с текстовыми asserts. Не тестировать бизнес-логику исключительно UI snapshots.

## 6. M4.1b ограниченный редактор (первый срез)

При явном `theia tui --role server|client --config FILE` TUI загружает существующий валидный TOML в типизированный черновик. В серверном разделе M4.1b редактируется только `server.inbounds[0].server_name`, в клиентском — `client.profiles[active].server`; другие поля и секреты не отображаются. `Enter/e` начинает ввод, `Enter` проверяет полный документ и принимает поле, `Esc` отменяет ввод. `Ctrl+S` проверяет и атомарно сохраняет файл, не посылая reload; `q`/`Esc`/переключение панели с dirty показывают выбор `s` сохранить / `d` отменить / `Esc` остаться. Изменённый внешним процессом файл не перезаписывается. Запуск TUI без `--config` остаётся обзором только для чтения. Сохранение сериализует typed TOML заново, поэтому комментарии исходного файла могут быть потеряны. Это не полный редактор inbound/users/profiles и не реализация управления сервисом; будущие формы, запросы IPC и Windows proxy остаются отдельными этапами.

## 7. M4.1c выбор inbound/профиля и формы из трёх полей

При `theia tui --role server|client --config FILE` доступен выбор **существующих** записей. `↑/↓` или `j/k` переключают серверные inbounds либо клиентские profiles по кругу; выбранный ID отображается текстом, клиентский профиль отмечается как активный или неактивный. Выбор записи для редактирования **не изменяет** `client.active_profile`. `Tab/Shift+Tab` циклически переводят фокус по трём безопасным полям выбранной записи. Для server доступны `server_name`, `h2_listen`, `quic_listen`, для client — `server`, `server_name`, `transport` (`auto`, `h2`, `h3`). Остальные значения (auth token references, TLS key refs, grants, digests) не выводятся и не редактируются. Ввод только явным `Enter/e`, подтверждение `Enter` проверяет весь typed TOML (включая пересекающиеся listen sockets, SNI, transport), ошибка оставляет прежний черновик и файл. Выход при dirty по-прежнему требует Save/Discard/Stay; Ctrl+S только атомарно сохраняет TOML в фоне, без reload/OS proxy/network. `theia tui` без `--config` остаётся read-only. Создание/удаление записей, управление пользователями и токенами, выбор активного профиля, изменение runtime и Windows proxy не входят в M4.1c. Сохранение переписывает TOML с потерей комментариев; внешний конфликт байтов блокирует запись лишь best-effort, не защищает от враждебной гонки в каталоге.

## 8. F-14 P0 — серверная выдача и клиентский импорт

Server TUI работает **локально на удалённом сервере**, в том числе через SSH, и не является удалённой HTTP-админкой. Client TUI работает на компьютере пользователя, управление сервером из неё не входит в MVP. Обе панели есть в одном бинарнике для соответствующей ОС; конфигурации server.toml/client.toml независимы.

Server → Inbounds → Users/Grants → New user (CSPRNG 32 bytes) → assign to selected inbound → Review/Validate → Save/Apply → **Export**. По умолчанию Secretless Profile; по отдельному подтверждению при генерации/ротации — Confidential Link/File, показываемая один раз и очищаемая с экрана при закрытии. Действующий token_sha256 невозможно обратить в ссылку с токеном, для нового экспорта с секретом нужна ротация.

Client → Profiles → Import → Paste / Open protected file → версия, безопасные поля, TLS trust и конфликт ID → Confirm → atomic secure credential write (никаких literal bearer tokens в TOML) → Validate/Save → отдельный выбор active и отдельный Start. Строка с токеном не отображается в обычной форме, в логах, history или диагностике; ссылка конфиденциальна, автоматический QR/clipboard — только opt-in с очисткой по возможности. Нельзя импортировать VLESS/VMess/Clash как Theia без настоящей совместимости; никаких произвольных web/SSRF fetch по URI. При отсутствии доверенной CA не делать insecure fallback. Подробности в docs/INVITATIONS.md.

M4.4a реализует **только доменный codec**, не UI/CLI вывоз токена и не сохранение импортированного профиля. Для F-14 P0 необходим полный M4.4b–d с Linux/Windows E2E.

## 9. M4.4b1 — создание пользователя и одноразовый показ ссылки

При явном `theia tui --role server --config FILE` и существующем валидном серверном TOML пользователь выбирает inbound (`j/k`, стрелки), затем `u` для ввода нового ID (1..64 ASCII-символов: буквы, цифры, `_`, `-`). `Enter` показывает подтверждение; `y` генерирует 32 криптографически случайных байта, сохраняет SHA-256 в новой записи users и добавляет ID только в allowed_user_ids выбранного inbound. При незавершённых изменениях, дубликате, невалидном ID, конфликте портов H2/H3 и ошибке RNG действие блокируется.

Сохранение полной проверенной конфигурации выполняется в фоновом worker с существующей проверкой внешнего изменения файла. **До успеха никакая ссылка и token не отображаются**. При ошибке доступны `r` повторить и `d` уничтожить черновик/токен. После сохранения отдельное `y` раскрывает конфиденциальный `theia://v1/...` только один раз; `n`/Esc вместо этого уничтожают токен; `Esc` после показа стирает URI с экрана и из состояния TUI. Пользовательская строка URI может быть длинной; вывод только в доверенном терминале/SSH, удобного безопасного экспорта в файл/clipboard/QR пока нет.

Важно: добавление записи в server.toml **не обновляет работающий процесс**. Секрет нельзя восстановить из digest; при его потере для работы понадобится будущая ротация. По-прежнему не реализованы отзыв/ротация старых пользователей, защищённый файл экспорта, управление users как список, импорт ссылки в клиентскую конфигурацию, системный прокси и IPC.
