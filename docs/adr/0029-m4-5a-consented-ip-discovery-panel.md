# ADR-0029: M4.5a, passive-first server TUI IP preview with consented ipify lookup

**Дата:** 2026-11-23. **Статус:** ограниченный функциональный PR, приёмка только после всех обязательных Linux/Windows CI на финальном SHA.

## Контекст и заданные ограничения

Серверный `theia tui` уже имеет typed TOML editor, одноразовую выдачу токена и асинхронное сохранение, но M3.5b2b1/2/4 остаются лишь библиотечными API. По целевой UX-спецификации F-18 мастер должен обнаруживать возможные собственные IP/CIDR и популярные домены **не начиная активных тестов автоматически**, а перед сторонним наблюдением публичного IP требовать отдельное информированное согласие. Поскольку ipify видит исходящий адрес, невидимый сетевой запрос при запуске сервера недопустим.

## Выбранный вертикальный срез

- В серверном экране TUI клавиша **`p`** (в том числе без загруженного конфигурационного файла) открывает *пассивный* просмотр. На Linux он вызывает только local `getifaddrs` через M3.5b2b1; на Windows честно показывает Unsupported и не угадывает IP/CIDR. Чистый `build_preview(PassiveOnly)` показывает количество публичных интерфейсных IP и seed-кандидатов (14). **Ни DNS, ни сетевых проверок, ни записи TOML, ни reload, ни OS proxy change при открытии.**
- Отдельное **`i`** показывает предупреждение о обращении к **`https://api64.ipify.org/`**: DNS + HTTPS, сторонний оператор увидит внешний IP, результат не подтверждает право на сканирование. **`y`** только из этого состояния отправляет явный `IpifyConsent::Approved` в M3.5b2b4. **`n`** оставляет просмотр пассивным, **Esc** закрывает панель; на клиентском/Help/Home экранах эти клавиши не запускают discovery.
- Доверенные CA загружаются из хранилища ОС через существовавший в lockfile `rustls-native-certs=0.8.5` (единственная новая прямая зависимость). При отсутствии валидных CA функция отказывает. Никаких insecure fallback/accept-invalid/подмены TLS roots нет. TLS strict 1.3/ALPN, pinned IP, ответные ограничения и общий 5s deadline остаются в `observe_default_ipify`.
- DNS, TLS и чтение хранилища CA выполняются в **отдельном OS-потоке** с отдельным Tokio runtime, результат передаётся в TUI через bounded single-value `std::sync::mpsc` receiver с `try_recv` в event-loop 50ms; терминал не блокируется. На Esc worker отменяется через `tokio::sync::oneshot` + `tokio::select!`, получатель удаляется. Нет фонового периодического опроса, ретраев и cache/persist.
- При успехе показывается сообщённый ipify IPv4/IPv6, статус `MatchesAssignedAddress` / `DiffersFromAssignedAddress`, локальное время наблюдения. Это **мнение доверенного по TLS внешнего сервиса**; нет доказательства NAT/ownership, TLS fingerprint пригодности, одобрения CIDR и права активно проверять соседние адреса. При любой ошибке показывается локальный безопасный код без IP/SNI/secret. Просмотр не вызывает `camouflage_batch` или команду сканирования.
- В режиме редактирования клавиша `p` является символом ввода, не навигацией. При грязном черновике просмотр запрещён с сообщением сохранить/отменить, чтобы не обходить проверку несохранённых изменений. Выдача секретной ссылки имеет приоритет и не пересекается с discovery.

## Given/When/Then (обязательные отрицательные тесты)

1. Given серверная TUI без конфигурации, when клавиша p, then появляется пассивный просмотр 14 доменов, без готового результата IP или согласия. Given `i`, when явный запрос согласия, then предупреждение с точным `api64.ipify.org`; `n` не инициирует сеть; Esc возвращает серверную панель.
2. Given клиентский, домашний или Help экран, when p, then нет доступа к server discovery.
3. Given серверный Editor с unsaved typed TOML, when p, then отказ до save/discard; никакого скрытого переключения панели.
4. Given state до `Confirm`, when запуск requested, then worker не создаётся. `Drop`/Esc отменяют долгую операцию. Никаких внешних DNS/TLS в CI: TUI-тесты проверяют только переключения состояний, а действительный TLS1.3/IP-echo уже проверяется отдельными loopback native Linux/Windows тестами M3.5b2b4.
5. Given неподдерживаемый native collector на Windows, then локальные IP не выдумываются. HTTPS может запускаться после самостоятельного согласия с валидными системными CA.

## Нереализовано и критерии принятия

В этом PR **нет** общего мастера `Проверить и подобрать → Применить`, списка ручных источников, подтверждения собственного CIDR, CT/RDAP/DNS passive lookup, bounded active scanner, сохранённого согласия, service IPC/rollback, Windows-native assigned-prefix collector, системного Windows proxy или REALITY/TLS-in-TLS. Даже положительный ipify не означает подтверждённый NAT. Внешняя HTTPS-сеть в CI запрещена.

Доступность и ошибки проверяются через существующий Rust test framework без ручного запуска на компьютере пользователя. Приёмка: cargo test --workspace --all-targets --locked; cargo fmt; cargo clippy -D warnings, native Windows smoke, BoringSSL, Chromium Linux/Windows E2E, exact-head GitHub `ci-gate` success. Изменение не меняет wire, TOML v1, invite v1, proxy/runtime или build target.
