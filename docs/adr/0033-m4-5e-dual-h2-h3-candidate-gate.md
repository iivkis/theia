# ADR-0033: M4.5e, REALITY candidate requires independently verified H2 **and** H3

**Date:** 2026-11-23. **Status:** limited H2+H3 *transport witness* in server TUI. **Not** a REALITY implementation, not Internet-range/domain auto scanning. Exact-head Linux/Windows CI mandatory.

## User requirement and honest scope

A discovered TLS camouflage candidate for future REALITY-*like* SmartTheia is **not dual-transport compatible** just because HTTPS/TCP works. Same candidate **exact IP + DNS SNI/SAN + port 443** must independently negotiate strict **TLS1.3 over TCP with ALPN=h2** and **QUIC/TLS1.3 over UDP with ALPN=h3**. Two source-specific verified observations must agree on the pinned IP, CA trust/expiry and SNI certificate identity. A partial H2 success cannot be reused as H3 proof and vice versa. A valid QUIC ALPN=h3 handshake alone does **not** establish HTTP/3 application SETTINGS, browser-like fingerprint or cryptographic REALITY server identity.

F-18 future candidate sources: native own assigned IP/CIDR and discovered HTTPS domains (popular seed catalogue included), with potential domain A/AAAA passive resolution. **This PR does not scan those CIDRs or resolve/scan domains.** Active checks of third parties require separately proved scope/authority, explicit target consent, DNS pinning/anti-SSRF and rate budgets; existence of a domain in the 14-name catalogue is never network permission. A CIDR entered for offline preview does not authorize all neighbors, and a public IP returned by ipify is not ownership proof. The currently working UI is exact-IP, **only an IP assigned to a local public UP interface and in the offline plan**.

## Implementation

1. `camouflage_h3_probe::probe_quic_h3` accepts the same `ProbeRequest` and `ProbeApproval` used by strict H2. Requires exact public IPv4/IPv6 UDP/443 or an isolated **exact loopback fixture**; rejects without approval/valid deadline/nonempty CA roots/valid DNS SNI **before socket I/O**. Uses production Quinn `ObservedEndpoint` with rustls TLS1.3, standard CA/SAN/SNI/expiry verifier, h3 ALPN and verified active BBR, no 0-RTT. Exact peer address must match. A per-request **≤5s total** timeout includes global 4-probe semaphore, bind and QUIC handshake. No DNS lookups, HTTP/3 request, QUIC retry fallback or H2 substitution, no insecure verifier and no positive evidence on any error. Supported results explicitly mark `alpn_h2: Unknown` and fingerprint Unknown.
2. `camouflage_dual::probe_dual_h2_h3` first validates **once** the exact approval, DNS SNI, root anchors, deadline and, for public IP, offline plan membership. No network starts if any preflight check fails. On success of preflight it performs **two independent** bounded handshakes against the **same** target IP: TCP+h2 and UDP+h3. Each error is retained independently, neither is a silent fallback for the other. `both_transports_verified()` requires both `Ok` and the **full** independently verified TLS facts (TLS1.3, chain, SAN/SNI, certificate validity, reachability, correct ALPN) for the same IP. No claim about HTTP/3 application semantics, REALITY/XTLS wire compatibility or anti-DPI. `reality_eligible()` remains **false** until separately implemented cryptographic server authentication/fingerprint etc.
3. Server TUI `p → t` still offers at most eight locally assigned UP public IPs with valid masks and a **server-config selected SNI**. Review screen displays the single IP and both TCP/443 and UDP/443 probes; **Enter/t** opens explicit consent, only subsequent **y** starts a worker with native CA trust, two bounded async probes and a single `Esc` cancel signal. The event loop stays unblocked. Never apply a configuration or persist permission.
4. Rendering shows two independent statuses, H2 and H3 evidence scores and elapsed times, or individually sanitized failure/Unknown. A genuine QUIC/TLS1.3 ALPN h3 proof gives **H3 evidence score 80/100, confidence 85%, eligible NO** because Theia fingerprint is Unknown, provided H3 was actually measured. H2 score is independent. If H3 fails, H3 score Unknown even if H2 is 80/100. Only when both pass the UI says **dual TLS/ALPN compatible**, explicitly **REALITY not ready**. All scores are checklist observations, not the probability of bypassing DPI.

## Test-first acceptance

- Native loopback real UDP/QUIC TLS1.3 `h3` positive with CA/SAN and BBR, wrong CA/name failures, missing/invalid approval and trust/invalid SNI/deadline before any UDP traffic, silently blackholed UDP timeout, no false H2 evidence. No external remote endpoints in CI.
- Native loopback **same exact IP:port for TCP+UDP**, same SNI and cert roots, both verified; separate negative: valid H2 while UDP blackholes => no dual compatibility, wrong CA fails both, non-approved target errors before network, public plan absence fail closed.
- Pure typed tests: mismatched H2 or H3 peer IP and missing ALPN/PKI fields fail gate even if report says `Ok`. `reality_eligible()` cannot become true solely from transport TLS observations. Debug redact exact IP/SNI from default logs. TUI tests simulate verified both, H2-only and H3-only, provenance mismatch, timeout, decline/cancel and no network until user y.
- Full exact-head native Linux+Windows CI: rustfmt, cargo test locked, Clippy `-D warnings`, BBR/BoringSSL, browser E2E, Windows smoke and final `ci-gate`. No manual testing or network against the seed domains.

## Remaining F-18/F-19 release blockers

Domain A/AAAA resolution with SSRF/rebinding guard, exact per-domain consent and IP pinning, authorized CIDR ownership evidence, per-range budgets, bounded multi-target H2+H3 scanner, H3 **HTTP** semantics/fingerprint evidence, TLS/HTTP backend shaping, REALITY-like cryptographic server authentication and anti-replay, candidate score ranking/Apply IPC rollback, F-19 nested-TLS classifier/flow shaping, Windows native interface collector. The new `both_transports_verified()` is a transport **prerequisite only**, not security-mode readiness. All of these remain open.
