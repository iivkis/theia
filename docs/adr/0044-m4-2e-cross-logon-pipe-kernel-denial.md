# ADR-0044: M4.2e — Windows cross-logon Named Pipe kernel-denial E2E

**Дата:** 2026-11-23. **Статус:** test-only PR; exact-head Windows CI pending.

## Контекст и угроза

ADR-0043 проверяет SID процесса, protected DACL и набор ACE реального
kernel pipe, но не проверяет попытку подключения под **другим** Windows
TokenUser SID. Чтение ACL или ошибка штатного CLI здесь недостаточны:
CLI вычисляет имя канала из SID самого клиента и может обратиться вообще
не к тому объекту.

## Решение

- Без изменений production runtime, сетевых listeners и wire-протокола.
  Отдельный ignored Rust integration test вызывается обязательным шагом
  Windows CI через scripts/windows-cross-sid-ci.ps1.
- В изолированном Windows runner создаётся временный непривилегированный
  локальный пользователь с криптографически случайным паролем. Пароль
  передаётся только через среду CI-процессов, не попадает в репозиторий
  или CLI argv; учётная запись удаляется в finally.
- Parent test создаёт **настоящий** WindowsServer::bind для своего SID и
  успешно выполняет status через штатный IPC. Рядом создаёт отдельный
  пустой локальный **test-only** pipe с явной Everyone DACL: это
  положительный контроль того, что второе logon действительно имеет
  возможность открывать pipe на этом runner.
- Дочерний pwsh под второй учётной записью сверяет TokenUser SID и отсутствие
  роли Administrator. Он пытается открыть оба **точных** имени pipe,
  переданных из parent, через Win32 CreateFileW. Контрольный pipe
  **обязан открыться**, защищённый pipe обязан вернуть ровно
  ERROR_ACCESS_DENIED (5). Ошибки FILE_NOT_FOUND, PIPE_BUSY, таймаут
  и невозможность создать логон являются **провалом теста**, не доказательством
  безопасности.
- Тестовый Everyone pipe локальный, не передаёт данные и живёт только
  в процессе теста. Оба pipe отвергают удалённые соединения. Процесс второго
  SID ограничен 45 секундами, общий helper 70 секундами.

## Ограничения

Тест подтверждает cross-logon отказ **другому непривилегированному SID**
у native Windows Named Pipe, но не защиту от LocalSystem,
администратора с особыми привилегиями, impersonation или полноценный
security audit. Полноценный Windows TUI PTY/SSH E2E, перезапуск
TLS/listener/quota и принудительный отзыв открытых туннелей остаются
отдельными этапами.

## CI acceptance

Обязательный windows-smoke вызывает отдельный native Windows сценарий,
не пропуская отсутствие полномочий runner для создания тестового
аккаунта. Полный Windows H2/H3 CAS Apply E2E и остальные проверки матрицы
остаются обязательными. Готовность признаётся только после exact-head
ci-gate с результатом SUCCESS; создание PR не является доказательством.
