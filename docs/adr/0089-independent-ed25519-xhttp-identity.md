# ADR-0089 — Independent Ed25519 server identity for SmartTheia XHTTP

Status: implementation submitted for exact-head mandatory native acceptance; independent security review and complete F-18/F-19 release acceptance remain open.

## Contract and provisioning

The explicit server mode smart-reality-v1 requires a separate reality_key = "file:/absolute/identity.der", containing an Ed25519 PKCS#8 DER private key (maximum 4096 bytes, bounded regular file, no symlink/reparse point, restrictive Unix mode). The existing TLS cert/chain/key and SAN remain required and are validated before bind. The identity key may not be the TLS key (including reuse of the same Ed25519 public key in another file). Keys are operator-provisioned; no automatic key generation, disclosure, TOFU or fallback. The client tls_profile is smart-reality-v1: followed by canonical unpadded base64url of the independent 32-byte public key. The existing CA and DNS name checks are mandatory. The selected XHTTP mode is stream-up. Both H2 and H3 use the same independent key.

The single replacement theia://v1/ invitation uses security_mode = "smart-reality", xhttp_mode = "stream-up", server_public_key (canonical 43-character base64url). No leaf_sha256 or private key reference in that combination. Other modes forbid server_public_key. Existing source/profile/grant/digest guards remain. No v2 or legacy envelope reader.

## Handshake and admission

After strict TLS 1.3 PKI/SAN/ALPN verification, both peers derive the ADR-0088 exporter key using the distinct h2/h3 contexts. Before emitting any bearer, the REALITY client sends one empty GET /v1/identity with no Authorization, content length, proof, query or trailers. On the explicit REALITY inbound only, the server validates EOF and the existing peer admission budget; it may issue one signature on that connection. The HTTP 200 response has no body or trailers and exactly one theia-server-identity header: canonical unpadded base64url of the 64-byte Ed25519 signature over fixed ASCII domain SmartTheia/REALITY/server-identity/v1, NUL, and the 32-byte exporter. No caller-supplied transcript or challenge is signed. Use ring Ed25519, not a new primitive. Exporter-derived temporary transcript is zeroized. The client verifies using its separately provisioned public key before the bearer is sent. No alternate mode or network fallback for an identity/TLS/protocol rejection.

Only after identity issuance may the two same-connection stream-up legs use the ADR-0088 HMAC admission. They still require exact route/method/bearer, grants, quotas, both leg proofs and one atomic logical admission. The independent signature is connection-specific; copying it to a fresh H2/H3 connection fails. Server cannot prove the client performed verification; normal clients must verify before sending credentials. Existing explicit experimental pinned and own-TLS profiles remain separate, not interchangeable or a release-ready third product choice.

## Lifecycle

Bounded signer bytes are captured with TLS material and included in the guarded snapshot fingerprint and identity hashes, so an external file replacement is not an auth-only or quota update. Fresh-port generation creation consumes captured material. Same-port TLS-only rotation is deliberately refused when either document has a REALITY inbound: the existing rollback slot only owns TLS acceptors, not the independent signer. A separate operator restart/fresh-port Apply is required. TUI Y accepts a hidden explicit file reference, validates the local TLS and independent identity, displays the public identity only, and confirms guarded save with y. Re-read exact source and public identities at confirmation. Candidate observations remain read-only and cannot authorize using another party's identity. No automatic runtime activation.

## Evidence and limits

Pure tests reject wrong key, wrong exporter, missing/duplicate signature, noncanonical profiles and malformed invitation combinations. Native loopback tests exercise H2 and H3 with the independent key, valid PKI, wrong key and old pinned mode refusal, no target dial on failure, portable invitation roundtrip and byte-exact bidirectional stream-up. Local editor tests cover key replacement between review and save and public export. Existing mandatory CI jobs remain unchanged. This is an authenticated server identity adapter, not hidden first flight, anti-probing, measured F-19 flow shaping or an independent crypto review. Resistance to active probing is not established. An active peer can identify the public handshake route, and a stolen bearer remains usable by its holder with valid identity verification. No performance, invisibility or release claim.
