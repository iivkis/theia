# ADR-0094 — Внешний TLS ресурс как целевой контракт SmartTheia REALITY

Статус: нормативное продуктовое решение, реализация не готова. Уточняет ADR-0084/0085/0086 и заменяет целевое толкование ADR-0089/0091/0092. Исторические wire/CI свидетельства остаются описанием существующего кода.

## Два режима, один XHTTP

SmartTheia REALITY должен использовать внешний HTTPS/TLS ресурс без собственного домена и TLS cert/key. Публичный сертификат стороннего ресурса не даёт права подписывать от его имени и не заменяет соответствующий приватный ключ. Импорт означает выбор внешнего ресурса и проверенных публичных параметров; независимая identity принадлежит Theia. Не импортировать, запрашивать или копировать чужие приватные ключи, не отключать проверку доверия. Xray REALITY — источник идеи внешнего ресурса и отдельной аутентификации, не требование совместимости и не готовый security backend для QUIC.

Собственный TLS — исключительно ручной X.509 сертификат/цепочка и соответствующий приватный ключ, проверенные имя, срок, доверие и соответствие ключа. Никакого поиска или генерации сертификатов в этом режиме. Два режима взаимоисключающие, XHTTP остаётся единственным транспортом, H2/TCP и H3/QUIC обязательны, QUIC-first с network-only fallback, BBR-first/CUBIC fallback без изменений.

## UX и границы

Мастер обнаруживает кандидатов из локальных сетевых данных, разрешённых IP диапазонов и каталога доменов. Пассивный обзор по умолчанию; активные проверки только по явно подтверждённому разрешённому scope, с ограничениями, отменой и SSRF защитой. Публичность сертификата или IP не означает разрешение на сканирование. Единый список показывает публичные сведения TLS, проверенную совместимость H2/H3, score, confidence, давность и объяснение; сортирует по пригодности и оценке. Оператор выбирает один ресурс, видит typed preview, отдельно подтверждает сохранение и защищённый транзакционный Apply/rollback. Ручной путь формирует тот же профиль и проходит тот же валидатор. Не выдавать оценку за вероятность обхода DPI.

## Реализация и приёмка

Прежний локальный TLS+Ed25519 backend требовал собственную TLS пару и проверял подпись после обычного TLS. Это не целевой REALITY. Он удалён из production runtime, TOML, приглашений и TUI; исторический CI не подтверждает новый backend. Старые профили отклоняются явно, без миграции и downgrade. Конкретная внешняя TLS trust model, wire, schema и независимая аутентификация требуют отдельного security ADR, проверенного backend и независимого review; H3 не выводится из H2 или из ALPN. Не задавать несуществующие поля и не изменять parser только ради декларации. Будущий контракт заменяет удалённый REALITY v1 без v2, legacy compatibility и третьего product mode; обязательны строгие негативные тесты и полная нативная приёмка. F-18 остаётся P0 open, F-19 отдельно. Описанный здесь wizard не является утверждением готовности или инструкцией по имитации стороннего сервиса.
