# M0.1 Rust transport API spike

**CI-only:** команды и сценарии ниже описывают исполнение внутри автоматических CI jobs; разработчик и пользователь не запускают их вручную. Ещё не автоматизированные проверки остаются открытыми требованиями.

**Not production Theia.** The isolated crate proves 1) `quinn::congestion::BbrConfig` is constructible and can be attached to client/server configs, 2) real in-memory HTTP/2 responds before request EOF and accepts later request chunks, and 3) the current HTTP/3 API exposes split send/receive halves.

```sh
cargo test --manifest-path spikes/m0_1/Cargo.toml --locked
```

**Verified by Linux + Windows CI:** real TCP/TLS 1.3 + ALPN `h2` with in-flight bidirectional HTTP/2 bodies and strict hostname/CA/ALPN rejection; real UDP/QUIC/TLS 1.3 + ALPN `h3` with HTTP/3 full-duplex response before request EOF, strict server identity verification, and active BBR controller type on both senders. **Additionally verified on Linux and Windows:** 768 KiB byte-exact QUIC delivery with active BBR while dropping every 20th *outgoing UDP transmit* after handshake, plus H2/TLS 1 MiB request bounded by withheld/released WINDOW_UPDATE capacity and 256 KiB response after request half-close. **Also verified:** 8 concurrently open HTTP/2 streams on one TLS session, 8 HTTP/3 streams on one QUIC connection, response before request EOF on each, and H2 RST_STREAM/H3 H3_REQUEST_CANCELLED isolating a cancelled stream without breaking the next request. **Also verified:** A single H2 response slow reader withholds 60 KiB window credit then receives all 512 KiB; H3 response slow reader with QUIC send_window=48 KiB and stream_receive_window=32 KiB blocks full 1 MiB enqueue until reading resumes. **Also measured as an unmodified TLS engine baseline (NOT browser impersonation):** default rustls TCP/TLS ClientHello from TLS records and plaintext rustls QUIC ClientHello before packet encryption. See `tests/client_hello_baseline.rs` and `docs/adr/0005-tls-fingerprint-baseline.md`. No SNI/random/session identifiers are logged. **Still missing:** production Theia proxy/inbound/SmartTheia auth, controlled comparative BBR RTT/jitter/loss/throughput benchmarks, hundreds of concurrent slow readers, mass cancellation races, fairness and peak-RSS tests, a real measured uTLS-like TLS/HTTP fingerprint and Windows system proxy integration. Never claim a production feature from this isolated spike.

Fingerprint negative-control: `client_hello::ClientHelloSummary::has_grease_extension()`, `has_alps()` (both 17513/17613) and `supported_groups` are exercised. Default rustls 0.23.46 H2 first flight has neither GREASE nor ALPS; **this is a version-pinned missing-feature check, NOT proof of Chrome parity**. See ADR-0005.

**Go uTLS reference instead of browser capture (H2 only):** `utls_reference/` builds the pinned `github.com/refraction-networking/utls v1.8.2` `HelloChrome_133` TCP/H2 first flight without any external network socket. Go `go.mod` and `go.sum` are pinned. CI runs Go unit tests and the explicit `--ignored` Rust comparison on Linux/Windows, using a temporary private fixture. It verifies GREASE+ALPS present in Go reference but absent from default rustls. The Go helper is **not part of the final Rust binary** and **does not supply H3 QUIC cryptography or an actual usable browser-like TLS backend**. See ADR-0005.

**Real Go uTLS Chrome133 -> Rust H2 E2E (test-only):** `utls_reference/cmd/h2_probe` is a Go client, not the production Theia stack. It makes a real TLS 1.3 TCP connection to the existing Rust h2 server, verifies x509 host/CA and ALPN `h2`, sends a minimal RFC 9113 H2 GET and receives HTTP 204. A Rust server peeks the actual network ClientHello and asserts GREASE/ALPS without saving raw TLS bytes. Ignored Rust tests `tests/utls_h2_loopback.rs` exercise positive, wrong hostname and untrusted CA paths and are explicitly run by Linux+Windows CI after compiling Go helper. The helper refuses non-loopback targets and **does not implement browser-identical H2 SETTINGS or H3/QUIC, and is not linked into the final Rust binary**. See ADR-0005.

Dependency versions and transitive resolution are pinned in the committed `spikes/m0_1/Cargo.lock` (generated by the first successful Linux CI run); all subsequent CI runs use `--locked`. See `docs/adr/0004-m0-1-feasibility.md` for the evidence ledger.
