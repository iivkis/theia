# M0.1 Rust transport API spike

**Not production Theia.** The isolated crate proves 1) `quinn::congestion::BbrConfig` is constructible and can be attached to client/server configs, 2) real in-memory HTTP/2 responds before request EOF and accepts later request chunks, and 3) the current HTTP/3 API exposes split send/receive halves.

```sh
cargo test --manifest-path spikes/m0_1/Cargo.toml --locked
```

**Verified by Linux + Windows CI:** real TCP/TLS 1.3 + ALPN `h2` with in-flight bidirectional HTTP/2 bodies and strict hostname/CA/ALPN rejection; real UDP/QUIC/TLS 1.3 + ALPN `h3` with HTTP/3 full-duplex response before request EOF, strict server identity verification, and active BBR controller type on both senders. **Additionally verified on Linux and Windows:** 768 KiB byte-exact QUIC delivery with active BBR while dropping every 20th *outgoing UDP transmit* after handshake, plus H2/TLS 1 MiB request bounded by withheld/released WINDOW_UPDATE capacity and 256 KiB response after request half-close. **Also verified:** 8 concurrently open HTTP/2 streams on one TLS session, 8 HTTP/3 streams on one QUIC connection, response before request EOF on each, and H2 RST_STREAM/H3 H3_REQUEST_CANCELLED isolating a cancelled stream without breaking the next request. **Still missing:** production Theia proxy/inbound/SmartTheia auth, controlled comparative BBR RTT/jitter/loss/throughput benchmarks, slow readers/mass cancellation races/hundreds of streams and peak-memory tests, a real measured uTLS-like TLS/HTTP fingerprint and Windows system proxy integration. Never claim a production feature from this isolated spike.

Dependency versions and transitive resolution are pinned in the committed `spikes/m0_1/Cargo.lock` (generated by the first successful Linux CI run); all subsequent CI runs use `--locked`. See `docs/adr/0004-m0-1-feasibility.md` for the evidence ledger.
